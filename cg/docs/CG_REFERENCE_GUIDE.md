# 첨부 스크린샷 분석과 CG 9종 기준

## 1. 자료 취급
첨부 스크린샷은 실제 방송 CG의 디자인 레퍼런스다. Claude Code 대화에 직접 첨부하거나 프로젝트의 `references/cg/` 등에 넣고 경로를 알려 준다. 이 문서·ZIP에는 이미지가 포함되어 있지 않다.

실제 파일을 모두 열어 확인한 뒤 관찰 사실과 추정을 구분한다. 보지 않은 이미지를 분석했다고 하지 않는다. 이미지가 없으면 목록과 분석 기준만 마련하고 실제 배치·폰트·색상은 NEEDS CONFIRMATION으로 남긴다. 이미지의 이름·수치는 레이아웃 예시이며 검증된 실제 DB로 가져오지 않는다.

## 2. PHASE 0 분석 항목
- 전체 화면에서 CG의 위치, 가로/세로 비율, 1920×1080 기준 좌표·폭·높이, 여백.
- 제목/데이터 영역, 행·열 개수, 좌우 비교/단일 목록/혼합 구조, 정렬·열 폭·정보 밀도.
- 제목·선수·숫자·보조 정보의 폰트 크기 관계, 숫자 정렬, 이름·전적 강조 방식.
- 배경색·행 그라데이션·테두리·강조색, 공통점과 유형별 차이.
- 실제 CG와 게임 화면/방송 배경을 분리해 투명 출력 범위를 식별.
- 긴 이름·닉네임·날짜·스코어·최대 행 수에서 넘침이 생기지 않을 기준.

원본 스크린샷 해상도가 1920×1080이 아니면 측정값과 환산 기준을 함께 기록한다. 픽셀 단위 완전 복제보다 재사용 가능한 테마·템플릿을 우선하되 결과는 레퍼런스에 최대한 가깝게 만든다. 관찰된 화면 구조와 아래 설명이 다르면 실제 이미지를 우선 참고하고 차이를 기록한다. 숫자 의미·집계 기준은 별도로 확인한다.

## 4. 공통 디자인과 출력
레퍼런스를 확인하기 전의 기본 방향: 검정/진회색 배경, 상단 Title Bar, 밝은 텍스트와 흰 숫자, 노랑/연두 강조, 금속/그라데이션 느낌의 행. 이는 출발점이며 관찰 결과로 조정한다.

CSS Variables 또는 Theme: cg-bg / cg-header-bg / cg-row-bg / cg-text / cg-muted / cg-accent / cg-border / cg-font. 실제 재사용되는 Container/Header/Table/Row/PlayerName/Score/Rank/Accent 등을 필요한 만큼만 분리한다.

기준 1920×1080, 기본 우측 하단, X/Y/Width/Height/Scale 조절. 페이지 body는 margin 0, background transparent, overflow hidden을 기준으로 한다. CG 패널 자체의 배경은 유지하고 나머지 캔버스만 투명하게 한다. 폰트는 시스템 또는 사용 허가된 폰트로 시작하고 Theme에서 교체한다.

CG는 공통 Stats Engine의 구조화된 결과를 표시한다. 외부 사이트 조회나 통계 집계를 컴포넌트마다 반복하지 않는다. 일반 PREVIEW 수정과 PROGRAM 전송은 DATA_AND_OVERRIDE 규칙을 따른다.

## 5. 템플릿별 확인 사항
- 승률: 어느 대회/기간의 경기·게임 기준인지, 상대 종족 범위, 소수점 규칙.
- 최근전적: 최신순 정렬, 표시 건수, 날짜 형식, 스코어의 선수 A/B 방향.
- 맞대결: 같은 선수 조합을 방향과 무관하게 조회하되 출력 스코어 방향은 일관되게 변환.
- 다승/연승: 집계 기간·종족 필터·동률 순위·연승 중단·진행 중 연승 종료일 표기.
- 예측: 중계진 예측 결과 데이터와 무효/미입력 집계 기준.
- 온라인: 실제 사이트·기간·게임 단위와 끝장전 기록의 구분.
- 더블 찬스: 방송 규칙과 집계 대상 확인; 일반 승률 공식을 이름만 바꿔 적용하지 않음.
- 풀세트: 9전 기준 `(4:5 패배 + 5:4 승리) / 유효 전체 경기수 × 100`을 기본 후보로 검토. 다른 bestOf가 섞이면 사용자 확인 후 처리. 과거 비율을 미래 승부 예측으로 설명하지 않음.

## 6. 화면 검수와 기록
각 유형을 실제 브라우저에서 렌더링해 레퍼런스와 비교한다. 글자 크기/열 폭/정렬/여백/강조색, 긴 이름·큰 수치·최대 행·데이터 없음, 투명 영역, SHOW/HIDE, 데이터 변경 시 흔들림을 확인한다.

OBS/vMix Browser Source 연결 후 1920×1080 크기·위치·투명도·WebSocket 변경을 별도로 확인한다. 브라우저만 확인했으면 실방송 출력은 미검증이라고 보고한다.

실제 분석 결과는 이 문서의 아래 표에 짧게 갱신한다. 파일명으로 유형을 추측해서 매칭하지 않는다.

분석일 2026-09-30. 원본은 2000×1121~1124다. 1920×1080에서 1.0417배 확대된 것으로 보고, 좌표는 ×0.96으로 환산한 1920 기준 값이다.

**공통 관찰**
- 위치·크기: 우측 하단. 오른쪽 끝에 붙고 아래 여백 약 4px. 크기 약 560×250, 시작 좌표 x≈1360, y≈826.
- 모서리: 좌상단만 둥글다(약 14px).
- 제목바: 높이 약 66px. 왼쪽 적갈색 → 차콜 → 오른쪽 청회색 그라데이션, 위쪽에 광택. 제목은 흰색 굵은 이탤릭에 그림자.
- 본문: 건메탈 그라데이션, 흰 글자, 승자는 노랑.

**추정**
- 폰트가 CG마다 다르다. 1·4번은 좁은 고딕, 2·3번은 각진 이탤릭, 5번은 둥근 고딕이다. 방송 폰트는 NEEDS CONFIRMATION.

## 7. 구현 결과 (PHASE 7, v0.2.0 — 2026-09-30)
9종 모두 같은 틀(560×250, 제목바 66px, 건메탈 본문, 승자 노랑)로 만들었다. 레퍼런스가 있는 5종은 배치를 맞췄고, 없는 4종은 #1(2열 비교)과 #4(금속 바 순위) 모양을 재사용했다. 화면 파일은 `www/app/templates/<slug>.view.php`, 스타일은 `www/assets/cg.css`다. 비교 캡처는 브라우저 확인(`tests/browser_check.cjs`)이 `type-<slug>.png`로 남긴다.

| # | slug | 모양 | 결정·차이 | 확인 필요 |
|---|---|---|---|---|
| 1 | race-win-rate | 2열 비교 | 세트 기준 (사용자 결정) | 폰트 |
| 2 | recent-race | 날짜·선수·스코어·상대 5행 | 대상 선수는 항상 왼쪽, 오래된 순. 경기 수 1~5 | — |
| 3 | head-to-head | 요약 바 + 날짜·스코어 행 | 요약 "0 : 4"는 끝장전 승수, 행은 세트 스코어. 제목 서수 = 지난 대결 수+1 | 요약 단위 |
| 4 | win-ranking | 금속 바 4행 (홀수 행 밝게) | **끝장전 승수** 순(2026-10-01 실데이터 대조: 박상현 39W 14L 73.6%, 도재욱 31W 26L 54.4% 일치), 같은 승수는 공동 순위(1, 2, 2, 4). 종족 필터는 선수의 주 종족 | 집계 기간 |

| 6 | online-h2h | 요약 바(온라인 맞대결) + 2열 비교 | 온라인 게임 1판 단위, 끝장전 기록과 분리. 제목 기본값 "매치포인트 온라인 상대 전적" | 온라인 기록 출처·기간·제목 |
| 7 | double-chance | 2열 비교 (종족 없음) | 끝장전당 2회 시도. 승 = 더블 찬스 세트(Results H > 0)의 A열 승자 수(상금 보정 탭 우선), 패 = 2 × 경기 수 − 승. 선수별 통계 탭과 다르면 송출 차단 (v0.4.0 확정) | — |
| 8 | win-streak | 금속 바 + 기간 | 끝장전 경기 단위 연승(세트 순서 기록 없음). 선수마다 최장 1개, 기간 = 시작일 ~ 종료일. 이어지는 연승의 종료일은 마지막 출전일(v0.4.0 사용자 결정). 종족 기본값 테란 | 기간 |
| 9 | full-set | 2열 비교 + 내역 | 9전만 집계. 비율 = (5:4 승 + 4:5 패) / 9전 경기 수. 화면에 "지난 풀세트 비율"로 표기(예측 아님) | 다른 bestOf 처리 |

- 긴 글자는 칸 너비에 맞춰 자동으로 줄인다(최소 60%). 9종 모두 MOCK 기준으로 넘치는 글자가 없는 것을 브라우저에서 확인했다.
- MOCK 표시는 제목바 왼쪽 위에 둔다(본문 숫자를 가리지 않게).

## 11. v0.6.1 — 항목마다 빼기 (빨간 −) (2026-10-01)
- 사용자 요청: 묶음 [CG에서 빼기]를 없애고, 제목·A 이름·B 이름 등 **모든 항목** 옆에 빨간 −. 누르면 빠지고, 다시 누르면(+) 복구.
- 타이틀 에디터
  - 항목 이름 왼쪽에 빨간 −(빼기). 뺀 항목은 초록 테두리 +(다시 넣기), 이름에 취소선·줄 흐리게, FINAL 칸 '빠짐'.
  - **Shift+클릭** = 같은 행·줄(묶음) 전체를 함께 빼기/다시 넣기 (예: 매치 프리뷰 '최근 5경기' A·B, 순위 CG의 '2행').
  - 위쪽 [모두 다시 넣기 (N)] = 이 CG에서 뺀 항목을 한 번에 복구. [뺀 항목 접기] = 뺀 항목은 이름과 + 만 남긴 얇은 줄로 (접은 채로 + 를 눌러 바로 복구).
  - 서버 동작은 그대로: `hide` 액션이 필드 키 목록(`fields`)을 받음. 묶음 이름은 받지 않는다.
- 송출 화면 규칙 (present가 `hid()`로 판단 — 뺀 값은 null로 오므로 '자료 없음'과 구분)
  - 뺀 항목은 **그 자리만 비운다**. 행·줄은 그 행·줄의 항목을 **모두** 뺐을 때만 사라진다.
  - 제목을 빼면 제목 줄과 아래 띠가 함께 빠진다 (14종 공통).
  - 승·패: "33승 21패"에서 승만 빼면 "21패" (`text_record_hid`), "17W 15L"도 같다 (`text_wl`).
  - 점수처럼 한 쌍인 값(세트 스코어 2 : 3, 맞대결 합계, 온라인 맞대결)은 한쪽만 빼도 통째로 빠진다.
  - present는 뺀 값이 null인 `$f`와 함께 `$f['@raw']`(빼기 전 값)를 받는다. `raw_val()`은 **강조·판단에만** 쓰고 화면 글자에는 쓰지 않는다.
    - 강조: 승률·점수·순위를 빼도 앞선 쪽·이긴 쪽·1위 줄 강조는 원래 값으로 (`top`, `a_win`/`b_win`, `lead`).
    - 매치 프리뷰 맞대결: '첫 맞대결'·자료 없음 판단도 원래 값으로. 4칸(A 승·B 승·A 세트·B 세트)을 모두 빼야 줄이 사라지고, 승만 빼면 '세트 N'만 남는다. 동률이면 세트 수와 관계없이 강조 없음. 맵 이름만 빼면 가운데 칸만 빈다.
  - 필수 항목(제목·이름 등)을 빼도 송출을 막지 않는다. 승률 같은 계산 항목의 '비어도 되는지'는 빼기 전 값으로 판단 (0승 0패에서 승만 빼도 막히지 않음).
  - 송출 중인 CG: 원래 비어 있던 항목('자료 없음')을 빼거나 다시 넣어도 '송출값과 다름' → UPDATE LIVE로 반영 (값 비교 + 뺀 항목 목록 비교).
- 테스트: `match_test` 항목별 5건 + 14종 × (항목 하나씩·모두) 빼고 그려지는지. 별도 검토(코드 리뷰) 지적 6건을 고치고 회귀 테스트로 남김.

- 같은 날 여러 경기의 순서 = Results 행 순서(먼저 입력된 경기가 먼저). 이전에는 이름순이었다.
- 기록별 상세 (`stats_match_records`의 `detail`):
  | 기록 | 상세 형식 | 내용 |
  |---|---|---|
  | 매치 연승·연패 | 경기 표 | 이어진 경기 최근 순 `날짜 · vs 상대 · 스코어 · 승/패`, 5경기 넘으면 1쪽 = 최근 5경기, 2쪽 = 6~10번째. 마지막 쪽 아래 '연승 직전 마지막 패배' / '연패 직전 마지막 승리'. 큰 숫자 옆에 범위(`최근 5경기 · 전체 10경기`)와 개인 최다 비교 |
  | 맞대결 연승 | 경기 표 | 이긴 선수 기준, 아래 '연승 직전 맞대결' |
  | 최근 5매치 (신규) | 경기 표 | 경기일 이전 최근 5경기(적으면 있는 만큼, `최근 3경기`처럼 수 표시). 큰 숫자 = 승, 단위 `승 N패`. 이상 경기가 끼면 확인 필요 |
  | 출전 간격 | 사실 표 | 마지막 출전(날짜 · vs 상대) / 결과(그 선수 기준 스코어 승·패) / 이번 경기까지 |
  | 맞대결 간격 | 사실 표 | 마지막 맞대결(날짜 · 승자) / 스코어(이름과 함께) / 이번 경기까지 / 상대전적 매치·세트(경기일 이전, 확인 필요 경기가 끼면 상대전적 줄은 생략) |
- 개인 최다 비교(연승·연패, 신규): 지금 이어지는 기록을 뺀, 이전에 끝난 같은 방향 기록 중 최장. 이상 경기에서는 이어진 것으로 보지 않는다. 문구는 시트 범위를 밝힌다 — `시트 기록(2019.05~) 기준 개인 최다 · 이전 최다 4연승` / `… 개인 최다 타이 (3연승)` / `개인 최다 6연승까지 2승 · 시트 기록(2019.05~) 기준` / 연패는 `개인 최다 N연패 · …`. '역대·통산'이라고 쓰지 않는다.
- 요약(매치 기록) 근거 한 줄 `r$n.note`: 기록 1개일 때만 큰 숫자 아래에 표시(2~3개는 줄 높이 때문에 그리지 않음). 내용: 연승·연패 = 개인 최다 비교(없으면 최근 경기), 출전 간격 = 마지막 출전, 맞대결 간격 = 마지막 맞대결 날짜·스코어, 맞대결 연승 = 최근 맞대결, 최근 5매치 = 최근 경기. 0.7.0에서 만든 페이지는 이 칸이 비어 있어 그대로 열리고 송출된다(근거 줄 없음).
- 흐름: 오늘 매치 창 기록 후보마다 **[상세 CG 추가]**(확정 기록만), 5경기 넘는 연승·연패에는 **[상세 6~N번째 경기]**. 페이지 추가 창에서 '기록 상세'를 고르면 기록 1개 + 쪽(1·2) 입력. 2쪽은 연승·연패 기록에만(그 외는 안내와 함께 거절).
- CG 구조(560, 높이 자동): 제목(선수 + 기록) → 큰 숫자·단위 | 범위·설명 + 개인 최다 비교 → 표(경기 표 머리글 `날짜 | 상대 | 스코어 (선수 기준) | 결과`, 승 = 강조색 칸) 또는 사실 표(항목 | 값) → 아래 한 줄(선택).
- 송출 막힘: 매치 기록과 같은 기준(확인 필요·해당 없음 → 이유와 함께 차단, 직접 입력하면 송출 가능). 시트 집계 대조(`stats_records_crosscheck`)도 같다.
