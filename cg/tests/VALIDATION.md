## 3. 이번에 발견·수정한 문제
- `no-referrer` 정책 때문에 실제 브라우저의 폼 POST에 `Origin: null`이 붙어 로그인·설치가 거부되던 문제.
  - 계정 화면은 `same-origin`, 송출 화면만 `no-referrer`로 나눴다. 회귀 테스트를 추가했다.
- 파비콘 요청이 404를 내 브라우저 오류로 잡히던 문제 → 빈 아이콘 지정.
- 압축 프로그램이 한글 파일명을 깨뜨리면 `시작-LAN.bat`이 `시작.bat`을 못 찾을 수 있던 구조.
  - 실제 동작을 영문 이름의 `launcher\` 폴더로 옮겼다.

## 4. v0.1.1 — 코드 검토 반영 (13건)
별도 코드 검토에서 높음 0건, 중간 5건, 낮음 8건이 나와 모두 고쳤다. 고친 항목마다 회귀 테스트를 추가했다.

**중간**
- **MySQL 동시 조작**: InnoDB의 일반 SELECT는 잠그지 않아, 두 운영자의 TAKE와 UPDATE LIVE가 서로 덮어쓸 수 있었다. 같은 초대 링크로 두 명이 가입할 수도 있었다.
  - 변경 트랜잭션 시작 때 설정 행을 `FOR UPDATE`로 잠가 한 줄로 처리한다(SQLite의 BEGIN IMMEDIATE와 같은 효과).
  - 테스트는 잠금을 빼면 실패하고 넣으면 통과하는 것을 확인했다.
- **UPDATE LIVE 범위**: 자동 갱신으로 바뀐 AUTO 값까지 송출에 나가던 문제.
  - 수정값(MANUAL)만 반영하고, 승률은 송출 스냅샷 기준으로 다시 계산한다.
  - AUTO 변경은 TAKE로만 반영하며, 확인창에 따로 안내한다.
- **UPDATE LIVE 확인창**: 창을 연 뒤 폴링으로 바뀐 값이 확인 없이 나갈 수 있던 문제 → 창을 연 순간의 상태를 고정해서 보낸다.
- **웹 로그인 쿠키**: 메신저 링크로 들어오면 로그인이 풀리던 문제 → SameSite=Lax로 바꿨다. 위조 방지는 CSRF 토큰과 Origin 확인이 맡는다.
- **단축키**: 송출 주소 칸에 포커스가 있을 때 Space를 누르면 복사와 TAKE가 함께 실행되던 문제 → 포커스된 버튼·주소 칸의 Space/Enter는 단축키로 처리하지 않는다.

**낮음**
- **실행기**
  - VC++ 런타임이 없을 때의 음수 오류 코드를 잡는다.
  - 로컬 전용으로 이미 실행 중인데 LAN 실행을 요청하면 경고한다.
  - 경로에 특수문자가 있어도 깨지지 않게 따옴표로 감쌌다.
- **로그인 시도 제한**: 확인 전에 먼저 센다. 동시 요청으로 제한을 우회할 수 없다.
- **승인 전 계정**: 송출 화면도 볼 수 없게 막았다.
- **TAKE 연타**: 요청이 끝날 때까지 잠근다.
- **저장 중 입력**: 요청 중에 고친 입력값을 지우지 않는다.
- **없는 레이어**: 404로 조용히 거부하고 오류 기록에 남기지 않는다.
- **라우터 경로**: `//`로 시작하는 주소를 경로 그대로 검사한다.

**v0.1.1 배포본 재확인**
- 자동 테스트 47건이 SQLite·MySQL에서 모두 통과했다.
- 배포 zip을 푼 PC 버전으로 브라우저 18항목이 통과했다.
- 배포 zip을 푼 웹 버전으로 설치 → 초대 → 승인 → TAKE → 비밀 송출 주소 흐름을 확인했다.
- 웹 패치 zip(0.1.0→0.1.1)에는 변경 파일 13개만 들어 있고, 버전 파일이 마지막 순서다.

## 5. v0.2.0 — CG 9종 (PHASE 7)
**집계 단위**: 사용자 결정에 따라 상대 종족 승률·다승은 세트 기준이다. 맞대결 요약·연승·풀세트·승자 예측은 원래 끝장전(경기) 단위다. 세트 순서 기록이 없어 세트 연승은 계산할 수 없다.

**브라우저 확인** (`tests/browser_check.cjs`, 기존 18항목 + 14항목 = 32항목 통과)
- 9종 각각: 페이지 추가 창에서 종류·입력값 선택 → 번호+Enter 큐 → F1 TAKE → 송출 화면에 기대 문구 표시 → 캡처(`type-<slug>.png`).
- 9종 모두 자동 축소 후 칸을 넘치는 글자 없음. 처음에는 긴 맞대결 제목이 제목바 여백 때문에 잘렸다 → 축소 계산에 여백을 반영해 고쳤다.
- 연승 순위: 종족 기본값 테란이 미리 선택됨.
- 긴 이름(5자)+닉네임(16자)도 이름·닉네임이 함께 줄어 칸 안에 표시됨. 자동 축소는 최소 60%까지라 12자 이름+16자 닉네임처럼 극단적인 경우는 잘린다(PREVIEW에서 확인 가능).
- 목록형 CG 에디터의 1~5행 구분 줄, 페이지 수정 창에 저장된 예측 자리 순서가 채워짐.

**레퍼런스 비교**: 01~05 배치(제목바·요약 바·금속 바·노랑 승자·1위 행 강조)를 맞췄다. 06~09는 레퍼런스가 없어 01·04 모양을 재사용했다.

**함께 고친 것**

**코드 검토 반영 (6건, 모두 회귀 테스트 추가)**

- [낮음] 행 필드에도 비율(share) 파생값을 쓸 수 있게 했다.

## 6. v0.3.0 — Google 시트 연결 (PHASE 8)
**자동 테스트 79건** (SQLite·MySQL 모두 통과). 실제 시트 내용은 저장소에 넣지 않고 합성 데이터로 확인했다.
- 세트 → 끝장전 묶기, 이상 경기(9세트 아님·동점·종족 변경)는 끝장전 통계에서 제외하고 세트 통계에는 포함.
- Results 형식 오류(이름·종족·날짜·같은 선수)는 행 번호와 함께 새로고침 실패 → 마지막 정상 데이터·PROGRAM 유지, STALE 표시.
- 교차 검증: 세트 전적 불일치, 끝장전 목록 불일치(종족 열 포함), 예측 순위표 불일치, 검증 탭 없음, 시트 집계에만 있는 선수·중계진, 주 종족 미정.
  - 해당 CG 필드(표시되는 제목·이름 포함)는 송출이 막히고, 운영자가 직접 입력하면 풀린다.
  - 관련 없는 CG는 영향이 없다.
- 서비스 계정
  - JWT 서명은 공개 키로 확인했다. 요청 범위는 읽기 전용이다.
  - 요청 순서는 토큰 → 탭 목록 → batchGet이다. 필요한 열만 읽고(Results A:F), 상금 탭은 읽지 않는다.
  - 가짜 Google 서버(php -S)로 실제 HTTP 스트림 전체 흐름을 확인했다. 다른 키로 서명하면 인증 실패 안내가 나온다.
  - 권한(403)·시트 없음(404)·인증 실패·서버 오류는 원인별로 안내한다. 메시지·로그·DB·화면에 토큰·개인 키가 없다.
  - 키 파일은 0600이고, 접근 차단 파일을 둔다. 삭제할 수 있다. 설정 변경은 관리자만 할 수 있고, 운영자에게는 시트 주소를 숨긴다.
- xlsx 가져오기
  - 날짜 서식 일련번호와 공유 문자열을 읽는다. API와 결과가 같다.
  - 깨진 파일과 zip이 아닌 파일은 거부한다.
- 닉네임
  - 입력한 것만 쓴다. 지우면 원래 값으로 돌아간다.
