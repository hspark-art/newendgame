# 끝장전 CG — 업데이트(패치) 안내

## 웹 버전 (FTP)
> 카페24 가상서버는 [SERVER_KR.md](SERVER_KR.md) 7절(업데이트)을 따릅니다. 아래 4번의 무결성 검사는 SSH `php app/cli.php check`로도 할 수 있습니다.

새 버전은 **패치 zip**(바뀐 파일만 담은 zip)으로 받습니다. 전체 zip으로 받아도 됩니다.

1. **방송이 없을 때** 진행합니다. 업로드 중에는 송출 화면이 잠깐 이전·새 파일을 섞어 읽을 수 있습니다.
2. 호스팅 관리 화면에서 DB 백업을 받습니다.
3. 패치 zip의 `PATCH_INFO.txt`를 엽니다. [추가]·[변경] 목록 순서대로 `files/www/` 안의 파일을 서버 웹 폴더의 같은 위치에 올립니다.
   - `app/version.json`은 **맨 마지막**에 올립니다. 이 파일이 새 버전 표시의 기준입니다.
   - `app/config.php`는 **절대 덮어쓰지 않습니다.** 패치에도 들어 있지 않습니다.
   - `install.php`는 다시 올리지 않습니다.
   - [삭제할 파일]이 있으면 서버에서 지웁니다.
4. 관리자 화면 → **파일 무결성 검사**를 누릅니다.
   - "모두 배포본과 같습니다"가 나오면 끝입니다.
   - "없음/다름" 파일이 나오면 그 파일을 다시 올리고 검사를 반복합니다.
5. 조작 패널을 새로고침(Ctrl+F5)합니다. DB 구조 변경이 있으면 첫 접속 때 자동으로 적용됩니다.

## PC 버전
- 새 버전 zip을 **새 폴더**에 풀고 그 폴더의 `시작.bat`을 실행하면 됩니다.
  - 작업 데이터(페이지 리스트·수정값·송출 상태)는 `%LOCALAPPDATA%\EndgameCG`에 있어 그대로 이어집니다.
  - 포터블 PHP(`runtime\php`)는 이전 폴더에서 복사해 오거나 `PHP준비.bat`을 다시 실행합니다.
- 이전 폴더는 문제가 없을 때까지 남겨 두면 언제든 되돌릴 수 있습니다. 단, 새 버전이 DB 구조를 바꿨다면 이전 버전으로 되돌릴 때 데이터 호환을 따로 확인해야 합니다.

## 개발자: 배포·패치 만들기
```bash
php tools/build_release.php dist          # dist/EndgameCG_PC_v버전.zip, dist/EndgameCG_Web_v버전.zip
php tools/build_patch.php 이전.zip 새.zip  # 바뀐 파일만 담은 패치 zip + PATCH_INFO.txt + patch.json(해시)
```
- 버전 번호는 `www/app/version.json` 하나만 올리면 됩니다. CSS·JS 주소에 버전이 붙어 브라우저 캐시도 새로 받습니다.
- DB 구조를 바꿀 때는 `www/app/migrate.php`의 `migrations()` 맨 끝에 새 번호를 추가합니다. 이미 배포한 번호의 내용은 고치지 않습니다.
