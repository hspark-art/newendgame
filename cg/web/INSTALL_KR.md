# 끝장전 CG 웹 버전 — 설치 안내

일반 웹호스팅(예: 카페24 웹호스팅)에 올려 쓰는 버전입니다. 팀원은 사이트 주소로 접속해 로그인하면 됩니다.

> 처음 설치하면 **MOCK(검증용 가짜 수치)** 로 시작합니다. 실제 끝장전 데이터는 [GOOGLE_SHEET_KR.md](GOOGLE_SHEET_KR.md)를 따라 Google 시트를 연결하세요.

## 1. 호스팅 준비
- **PHP 8.1 이상** (호스팅 관리 화면에서 PHP 버전을 8.x로 선택)
- **MySQL 또는 MariaDB** — 기존 채팅·상품 관리와 같은 DB를 써도 됩니다. 이 프로그램의 테이블 이름은 모두 `cg_`로 시작해 겹치지 않습니다.
- **SSL(https)** 적용 권장. 로그인 정보가 오가고, 비밀 송출 주소를 보호하기 위해서입니다.
- PHP 확장: `pdo_mysql`, `mbstring`, `openssl`(Google 시트 연결), `zip`(xlsx 가져오기) — 대부분의 호스팅에 기본 포함
- 서버에서 `https://oauth2.googleapis.com`·`https://sheets.googleapis.com` 으로 나가는 접속이 허용되어야 합니다 (막혀 있으면 xlsx 가져오기를 쓰세요).
- xlsx 가져오기를 쓰려면 PHP `post_max_size`가 16M 이상이어야 합니다.

## 2. 설정 파일 만들기
1. 배포 zip의 `www/app/config.sample.php`를 같은 폴더에 `config.php`로 복사합니다.
2. 호스팅 관리 화면에서 확인한 **DB 이름·아이디·비밀번호**를 `db` 항목에 입력합니다.
3. `config.php`는 서버 접속 정보가 들어 있으므로 다른 사람에게 보내거나 저장소에 올리지 않습니다.
4. (권장) `secrets_dir`에 웹 폴더 밖의 쓰기 가능한 폴더를 지정합니다. Google 서비스 계정 키를 보관하는 곳입니다. 비워 두면 `app/storage/secrets`(웹 접근 차단)를 씁니다.

## 3. 파일 올리기 (FTP)
- FTP 프로그램(파일질라 등)으로 배포 zip의 `www` 폴더 **안의 내용 전체**를 올립니다.
  - 카페24는 웹 폴더가 `www`입니다.
  - 기존 사이트와 함께 쓰려면 `www/cg/`처럼 하위 폴더에 올려도 됩니다. 모든 주소가 상대 경로라 그대로 동작합니다.
- `app/.htaccess`가 함께 올라가야 합니다. 이 파일이 설정·DB 폴더를 외부에서 열지 못하게 막습니다.
  - 확인: 브라우저로 `https://내주소/app/config.php`에 접속했을 때 **403 또는 404**가 나와야 합니다.

## 4. 첫 관리자 만들기
1. 브라우저에서 `https://내주소/install.php`에 접속합니다. DB 테이블은 자동으로 만들어집니다.
2. 관리자 아이디·이름·비밀번호(12자 이상)를 입력합니다. 기본 비밀번호는 없습니다.
3. **FTP로 서버의 `install.php`를 삭제**합니다. 관리자 화면 맨 위의 경고가 사라지면 된 것입니다.

## 5. 팀원 초대 → 승인
1. 관리자 → **초대 링크 만들기** (메모, 유효 시간 1~7일)
2. 화면에 한 번만 표시되는 링크를 복사해 대상자에게 직접 전달합니다(메신저 등). 메일 발송 기능은 없습니다.
3. 대상자가 링크로 들어와 아이디·이름·비밀번호를 입력하면 **가입 신청(승인 대기)** 상태가 됩니다.
4. 관리자 → 계정 목록에서 **승인**합니다.
   - 링크를 가진 사람은 누구나 신청할 수 있습니다. 이름·아이디가 실제 대상자인지 확인한 뒤 승인하세요.
5. 역할
   - **운영자**: 조작 패널 전체를 사용합니다.
   - **관리자**: 운영자 권한에 더해 계정·초대·송출 주소·시스템 정보를 관리합니다.

**계정 관리 참고**
- 비밀번호 분실: 관리자 → 해당 계정 **재설정 링크**(1시간, 1회용)를 발급해 전달합니다.
- 계정 정지: 그 계정의 로그인이 즉시 끊기고 다시 로그인할 수 없습니다.
- 로그인을 5분 안에 10번 틀리면 그 아이디는 5분 동안 로그인할 수 없습니다.
- 모든 운영자는 **같은 작업 공간**(페이지 리스트·송출 상태)을 함께 씁니다.

## 6. OBS / vMix 연결
- 조작 패널 오른쪽의 **송출 주소**(또는 관리자 → 비밀 송출 주소)를 클릭해 복사합니다.
  - 형식: `https://내주소/output.php?t=비밀값&layer=1`
- OBS 브라우저 소스 또는 vMix 웹 브라우저 입력에 넣고 크기를 **1920 × 1080**으로 맞춥니다.
- 이 주소는 로그인 없이 **송출 화면만** 볼 수 있습니다. 밖으로 공유하지 마세요.
- 주소가 새어 나갔으면 관리자 → **송출 주소 재발급**을 누릅니다. 이전 주소는 즉시 동작하지 않으며, OBS/vMix에 새 주소를 다시 넣어야 합니다.
- 인터넷이 끊겨도 송출 화면은 마지막 화면을 유지하고 다시 연결을 시도합니다.
- 실시간 반영은 0.3초 간격으로 확인합니다. 일반 웹호스팅은 WebSocket을 지원하지 않기 때문입니다.

## 7. 업데이트
- 새 버전이 나오면 [PATCHING_KR.md](PATCHING_KR.md)를 따릅니다.
- 핵심 순서: 변경된 파일만 FTP로 덮어쓰고 `app/version.json`은 **마지막**에 올린 뒤, 관리자 → **파일 무결성 검사**로 확인합니다.
- `app/config.php`는 절대 덮어쓰지 않습니다. `install.php`는 다시 올리지 않습니다.
- DB 구조 변경은 첫 접속 때 자동으로 적용됩니다.

## 8. 백업
- 호스팅 관리 화면의 **DB 백업** 기능으로 `cg_`로 시작하는 테이블을 정기적으로 내려받습니다.
- 조작 패널의 **내보내기**로 페이지 리스트를 파일로 저장해 둘 수 있습니다. PC 버전에서 [가져오기]할 수도 있습니다.
- 백업에는 계정 정보와 비밀 송출 주소가 들어 있으므로 보관에 주의하세요.

## 9. 문제 해결
| 증상 | 확인할 것 |
|---|---|
| 모든 화면이 "설정 파일이 없습니다" | `app/config.php`가 올라갔는지 확인 |
| 흰 화면 / 500 오류 | PHP 8.1 이상인지 확인. `config.php`의 `debug`를 잠깐 `true`로 바꾸면 오류 내용이 보입니다(확인 후 `false`) |
| 로그인 후 자꾸 로그아웃됨 | `config.php`의 `session_path`에 웹 폴더 밖의 쓰기 가능한 폴더를 지정 |
| 폼 제출 시 "보안 확인에 실패" | 화면을 새로고침한 뒤 다시 시도. 주소를 http/https 섞어 쓰지 않았는지 확인 |
| 송출 화면이 비어 있음 | 주소의 `t=` 값이 최신인지(재발급 여부) 확인. 조작 패널에서 TAKE 했는지 확인 |

## 10. 검증 범위
- **확인한 것**: 개발 환경에서 PHP 내장 서버 + SQLite/MariaDB 10.11로 계정·권한·송출 흐름 자동 테스트, Chromium 브라우저 확인.
- **실제 운영 전에 직접 확인할 것**
  - 실제 호스팅(Apache, `.htaccess`), HTTPS
  - 호스팅 요청 수 제한(송출 화면 1개당 초당 약 3회 요청)
  - OBS/vMix 연결
